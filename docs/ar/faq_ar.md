# الأسئلة الشائعة (FAQ)

## س1: خطأ في FFmpeg أو مشاكل الترميز (UTF-8)
غالبًا السبب هو مسار الملف أو أحرف غير مدعومة في اسم الملف. تأكد من أن:
- المسار لا يحتوي على أحرف غريبة أو مسافات غير متوقعة.
- أسماء الملفات محمية باقتباس عند تمريرها إلى أوامر سطر الأوامر.
- إذا كانت هناك ملفات بأحرف غير لاتينية (مثلاً صينية)، فاحفظ filelist.txt بصيغة UTF-8.

## س2: لا يظهر ملف الفهرس بعد "التدريب بنقرة واحدة"
قد يكون التدريب قد أنشأ النموذج لكن لم يكتمل إنشاء الفهرس بسبب قيود الذاكرة أو حجم البيانات. الحلول:
- اضغط "تدريب الفهرس" يدويًا بعد اكتمال التدريب.
- تحقق من السجلات داخل `logs/<experiment>/` لرسائل الخطأ.

## س3: النموذج لا يظهر في واجهة "استدلال الجرس" بعد التدريب
- اضغط "تحديث قائمة الجرس" في الواجهة.
- تأكد من وجود ملف `weights/<your_model>.pth` أو ملف index صالح في `logs/<experiment>/`.
- راجع سجلات التدريب للعثور على أي أخطاء أثناء الحفظ.

## س4: كيف أشارك نموذجاً أو أستخدم نماذج الآخرين؟
- النماذج الصالحة للاستدلال توجد عادة في `assets/weights/` كملفات `.pth` بحجم ~60+ ميغابايت.
- لا تشارك ملفات checkpoints الخام (logs/...) مباشرة — استخرج نموذجًا صغيرًا من علامة تبويب ckpt قبل المشاركة.

## س5: مشاكل اتصال أو فقدان الاستجابة
- قد تكون نافذة الطرفية مغلقة أو الحاوية أغلقت.
- أعد تشغيل الواجهة وراجع سجل النظام.

## س6: رسالة 'Expecting value: line 1 column 1 (char 0)'
- غالبًا ناتجة عن Proxy محلي أو JSON فارغ؛ عطّل أي وكيل وحاول إعادة تحميل الصفحة.

## س7: كيفية التدريب والاستدلال عبر سطر الأوامر
مثال استدعاء لاستدلال بسيط (Windows path example):

```bash
python myinfer.py 0 "E:\\path\\to\\input.wav" "logs/myexp/added.index" harvest "output.wav" "assets/weights/my-model.pth" 0.6 cuda:0 True
```

الأوساط:
- `input_path`: مسار ملف الإدخال
- `index_path`: مسار ملف الفهرس
- `f0method`: طريقة استخراج النغمة (مثال: harvest أو rmvpe)
- `model_path`: مسار النموذج (`assets/weights/*.pth`)
- `device`: الجهاز مثل `cuda:0` أو `cpu`

## س8: خطأ CUDA / نفاد الذاكرة
- للتدريب: خفّض `batch_size` أو استخدم نماذج ومعدلات عينة أخف (32k).
- للاستدلال: قلّل إعدادات الذاكرة في `config.py` (`x_query`, `x_pad`) أو استخدم جهازًا ذا ذاكرة أكبر.

## س9: ما هو العدد الأمثل للدورات (epochs)؟
- لبيانات قصيرة النوع/منخفضة الجودة: 20–50 epochs.
- لبيانات نقية وكاملة: 200+ قد يكون مفيدًا.

## س10: مستوى بيانات التدريب (المدة المطلوبة)
- يوصى بـ 10–50 دقيقة. نتائج جيدة غالبًا مع 5–10 دقائق إذا كانت الجودة ممتازة.

## س11: ما هو "index rate" وكيف أضبطه؟
- يحدِّد مزيج استرجاع الخصائص بين مصدر الاستدلال ومجموعة التدريب.
- `index_rate = 1.0` يعني الاعتماد الكامل على الفهرس؛ قلّله لتقليل تسرب النغمة.

## س12: اختيار GPU للاستدلال
- في `config.py` اختر `device` المناسب (مثلاً `cuda:0`). تفحص معلومات GPU في واجهة التدريب لمطابقة الأرقام.

## س13: مواصلة التدريب ببيانات جديدة
1) ضع ملفات wav الجديدة في path2.
2) عالج البيانات واستخراج الخصائص لنفس اسم التجربة الجديد.
3) انسخ آخر ملفات G/D من تجربة سابقة إذا أردت الاستئناف من نقطة سابقة.

## س14 — س18: أخطاء شائعة وحلول قصيرة
- `llvmlite.dll` (Windows): ثبّت Visual C++ Redistributable (vc_redist.x64.exe).
- أخطاء حجم التنسور: تحقق من توحيد معدّل العينة ولا تستأنف تدريبًا بمعدل عينة مختلف دون تغيير اسم التجربة.

- إضافة أمثلة أو لقطات شاشة حسب الحاجة.
